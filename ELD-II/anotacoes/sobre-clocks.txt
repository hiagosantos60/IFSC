# USO INDEVIDO DE RESET ASSÍCRONO
- Não se usa reset assíncrono para zerar registro durante operação, somente na inicialização do sistema para estabilizar os sinais.
- Se aparecer lógica para o sinal de reset, é um forte indício de que temos erros no código VHDL. 
- Glitches de transição são pulsos indesejados que ocorrem na saída de um circuito digital quando há uma mudança nos sinais de entrada. Eles acontecem devido ao atraso de propagação inerente aos componentes eletrônicos.

## Exemplo de código que vai dar problema na questão do reset:
``` vhdl
--=============================
-- Listing 9.1 async clear
--=============================
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity mod10_counter is
    port (
        clk, reset : in  std_logic;
        q          : out std_logic_vector(3 downto 0)
    );
end mod10_counter;

-- arquitetura problemática
architecture poor_async_arch of mod10_counter is
    signal r_reg     : unsigned(3 downto 0);
    signal r_next    : unsigned(3 downto 0);
    signal async_clr : std_logic;
begin

    -- Register process
    process(clk, async_clr)
    begin
        if (async_clr = '1') then
            r_reg <= (others => '0');
        elsif (clk'event and clk = '1') then
            r_reg <= r_next;
        end if;
    end process;

    -- Asynchronous clear logic
    async_clr <= '1' when (reset = '1' or r_reg = "1010") else
                 '0';

    -- Next state logic
    r_next <= r_reg + 1;

    -- Output logic
    q <= std_logic_vector(r_reg);

end poor_async_arch;

-- arquitetura correta
architecture two_seg_arch of mod10_counter is
    signal r_reg  : unsigned(3 downto 0);
    signal r_next : unsigned(3 downto 0);
begin

    -- Register process
    process(clk, reset)
    begin
        if (reset = '1') then
            r_reg <= (others => '0');
        elsif (clk'event and clk = '1') then
            r_reg <= r_next;
        end if;
    end process;

    -- Next-state logic
    r_next <= (others => '0') when r_reg = 9 else
              r_reg + 1;

    -- Output logic
    q <= std_logic_vector(r_reg);

end two_seg_arch;
```

# CLOCK DERIVADO
- Subsistemas podem funcionar com clocks diferentes, isso cria um problema por estar deformando o sinal de clock, atrasando ele para uma parte e para outra não, quebrando o sincronismo entre as partes de um sistema complexo. Além de que a análise de timing do circuito é totalmente quebrada.

# GATED CLOCK
- É quando o clock é alterado com portas lógicas para gerar um comportamento diferente, mesmo que fora de padrão. Entretanto, esse tipo de manobra se torna complicado para fazer uma rede de distribuição de clocks e o clock resultante pode sofrer com glitchs resultantes do sinal de enable. Então como regra: O CLOCK NÃO DEVE SER MANIPULADO.
- A solucação para o código abaixo seria utilizar um sinal de enable assíncrono que está na entidade e não usar esse sinal de clk criado na arquitetura

Exemplo de código:
``` vhdl

library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity binary_counter is
    port (
        clk, reset : in  std_logic;
        en         : in  std_logic;
        q          : out std_logic_vector(3 downto 0)
    );
end binary_counter;

-- arquitetura problematica
architecture gated_clk_arch of binary_counter is
    signal r_reg     : unsigned(3 downto 0);
    signal r_next    : unsigned(3 downto 0);
    signal gated_clk : std_logic;
begin

    -- Register process
    process(gated_clk, reset)
    begin
        if (reset = '1') then
            r_reg <= (others => '0');
        elsif (gated_clk'event and gated_clk = '1') then
            r_reg <= r_next;
        end if;
    end process;

    -- Gated clock logic PROBLEMA
    gated_clk <= clk and en;

    -- Next-state logic
    r_next <= r_reg + 1;

    -- Output logic
    q <= std_logic_vector(r_reg);

end gated_clk_arch;

-- arquitetura correta
architecture two_seg_arch of binary_counter is
    signal r_reg  : unsigned(3 downto 0);
    signal r_next : unsigned(3 downto 0);
begin

    -- Register process
    process(clk, reset)
    begin
        if (reset = '1') then
            r_reg <= (others => '0');
        elsif (clk'event and clk = '1') then
            r_reg <= r_next;
        end if;
    end process;

    -- Next-state logic
    r_next <= r_reg + 1 when en = '1' else
              r_reg;

    -- Output logic
    q <= std_logic_vector(r_reg);

end two_seg_arch;

```
